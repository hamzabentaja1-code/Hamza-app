# HamZa v0.8.0

مشروع Android مستقل باسم HamZa والحزمة `com.hamza.app`.

## الموجود حالياً
- المنتجات مع ثمن الشراء وثمن البيع وهامش ربح الوحدة والربح المحتمل للمخزون، وإضافة/تغيير/حذف صورة المنتج ومعاينة مكبرة والبحث والتعديل، مع حفظ محلي عبر AsyncStorage؛ الزبناء والموردون أيضاً.
- نقطة بيع POS: بحث بالاسم، سلة متعددة المنتجات، تعديل الكمية، تخفيض عام، اختيار الزبون وطريقة الأداء، التحقق من المخزون، تسجيل البيع وتحديث المخزون وإصدار وصل PDF.
- المبيعات والمشتريات وتحديث كمية المخزون، مع سجل حركات المخزون والجرد الفعلي وتسوية الفروقات حسب المخزن النشط.
- مخازن متعددة مع مخزن رئيسي افتراضي، أرصدة مستقلة لكل مخزن، تحويلات خروج/دخول متوازنة، ومنع التحويل أو البيع فوق رصيد المخزن؛ مجموع المخزون العام لا يتغير بالتحويل.
- مرتجعات الزبناء الجزئية: التحقق من الكمية المتبقية، تعديل صافي المبيعات والربح المحسوب بالتكلفة المسجلة، واختيار إعادة المنتج للمخزون أو عدم إعادته.
- سجل أداءات الموردين: دفعات جزئية بالسنتيم، وصل PDF، وإمكانية عكس أداء محذوف مع إعادة حساب الدين المستحق.
- أوامر شراء للموردين مع تاريخ تسليم متوقع، استلام جزئي أو كامل، تحديث المخزون ومتوسط التكلفة، وطباعة أمر الشراء PDF.
- مرتجعات الموردين الجزئية مرتبطة بالشراء، تخصم الكمية من المخزون وقيمة المرتجع من الدين، وتسمح بإلغاء المرتجع مع عكس المخزون.
- صندوق نقدي أساسي: رصيد افتتاحي، مداخيل ومصاريف نقدية، منع الصرف فوق الرصيد، وتصدير دفتر الصندوق PDF.
- الحسابات البنكية: حسابات متعددة، أرصدة افتتاحية، إيداعات وسحوبات، تحويلات داخلية مزدوجة، وتسوية يدوية مع كشف البنك. تحويل الصندوق إلى البنك والعكس يسجل حركتين متوازنتين ذرياً مع التحقق من الرصيد.
- مبيعات POS بالبطاقة أو التحويل كتتسجل في الحساب البنكي المختار، مع منع إتمام البيع إذا ما تختارش حساب بنكي.
- تصنيف المصاريف وربطها بالمشاريع مع تأكيد الحذف وإمكانية استخراج وصل PDF.
- المصاريف المتكررة: قواعد أسبوعية وشهرية وسنوية، توليد الاستحقاقات الفائتة مرة واحدة فقط، ومنع التكرار مع إمكانية الإيقاف والتفعيل.
- الأجندة: تجمع مواعيد المهام وأوامر التركيب واستحقاقات المصاريف والفواتير غير المؤداة حسب الفترة، وتبيّن المواعيد المتأخرة.
- إعدادات ملف الشركة: الاسم والعنوان والهاتف والبريد وICE وRC وIF والشعار، مع تضمينها في وثائق PDF.
- تقارير PDF أساسية للمبيعات والمشتريات الصافية بعد مرتجعات الموردين والمخزون وديون الزبناء والموردين والصندوق والربح المحسوب؛ فلاتر الفترات والمقارنات المتقدمة ما زالت غير مكتملة.
- بيانات المنتج تشمل الصنف والماركة والوحدة والنوع/المقاس، مع البحث والاستيراد الجماعي وتصدير CSV.
- دعم أولي لإمكانية الوصول: تسميات لقارئ الشاشة، حالات الاختيار، التنقل بلوحة المفاتيح وتوسيع مساحة اللمس؛ راجع `docs/ACCESSIBILITY.md` لاختبارات TalkBack المتبقية.
- كشوف حساب PDF للزبناء والموردين، تجمع الفواتير أو المشتريات والأداءات المسجلة والرصيد المتبقي.
- ملفات الزبناء والموردين تحفظ الرصيد الافتتاحي وسقف الدين وأجل الأداء، وتدخل الأرصدة الافتتاحية في إجمالي المستحقات. تحويل عرض السعر إلى فاتورة كيراقب سقف ائتمان الزبون ويحسب تاريخ الاستحقاق حسب أجل الأداء.
- المصاريف، عروض الأسعار، الأداءات والتقارير الأولية.
- المشاريع: الزبون والميزانية والتواريخ والحالة والملاحظات، مع احتساب مصاريف المشروع من المصاريف المرتبطة به.
- المهام: ربط بالمشروع، المسؤول، الأولوية، موعد الإنجاز، المدة التقديرية، وتغيير الحالة مع الإضافة والتعديل والحذف.
- طلبات التركيب وأوامر العمل: دورة من الطلب والبرمجة إلى بدء العمل والإكمال أو الإلغاء، مع ربط الزبون والمشروع والتقني والمعدات.
- التقنيون والمعدات: ملف تقني بالتخصص والهاتف وثمن الساعة، ومعدات بمرجع ورقم تسلسلي وحالة التوفر والتخصيص.
- ساعات العمل: تسجيل التاريخ والتقني والساعات وثمن الساعة، وحساب تكلفة العمل بالسنتيم لكل أمر عمل وتقني.
- إنشاء PDF ومشاركته لبعض وثائق البيع والمصاريف والأداءات.
- تصدير نسخة احتياطية JSON واسترجاعها يدوياً عبر النسخ واللصق، مع التحقق من بنية النسخة قبل الاسترجاع.
- واجهة عربية وفرنسية مع تبديل اللغة وحفظ الاختيار؛ ما زالت مراجعة الترجمة الشاملة واختبار تخطيط RTL/LTR مطلوبين.

## البناء والفحص
GitHub Actions في سير التحقق الحالي ينفذ اختبارات وحدات المجال وفحص TypeScript فقط، ولا يبني APK. لم يتم إصدار APK لهذا التغيير.
قبل التوزيع يجب إعداد مفتاح توقيع دائم محفوظ خارج المستودع في GitHub Actions Secrets، ثم بناء APK واختباره على Android ومراجعة صلاحيات التطبيق ونتائج Accessibility Scanner وTalkBack.

## وحدات منطق الأعمال
ما زال استيراد كشوف البنك آلياً ومطابقة الحركات المستوردة، صلاحيات المستخدمين، تسوية الأعمال ومرفقاتها، تصنيفات المعدات، تنبيهات النظام والتقويم الكامل، دورة الوثائق المتقدمة، والفلاتر والرسوم المتقدمة تحتاج استكمالاً.

## حدود النسخة
هذا مشروع مستقل لإعادة تنفيذ الوظائف المعروفة، وليس نسخة مطابقة من YanCommerce، ولا يتصل بخادمه أو حساباته. البيانات محلية على الجهاز. المشروع ما زال نموذجاً أولياً، ويلزم استكمال الواجهات والاختبارات قبل الاستعمال التجاري.

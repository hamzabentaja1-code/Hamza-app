# HamZa v0.8.0

مشروع Android مستقل باسم HamZa والحزمة `com.hamza.app`.

## الموجود حالياً
- المنتجات مع ثمن الشراء وثمن البيع وهامش ربح الوحدة والربح المحتمل للمخزون، وإضافة/تغيير/حذف صورة المنتج ومعاينة مكبرة والبحث والتعديل، مع حفظ محلي عبر AsyncStorage؛ الزبناء والموردون أيضاً.
- نقطة بيع POS: بحث بالاسم والمرجع والباركود، تصفية الصنف والمخزون المتوفر، تعليق السلال واسترجاعها، تعديل الكمية، تخفيض عام، اختيار الزبون وطريقة الأداء، تحديث المخزون وإصدار وصل PDF.
- المبيعات والمشتريات وتحديث كمية المخزون. دورة شراء مستقلة تدعم طلب الشراء وأمر الشراء والاستلام المرتبط بالمخزن وفاتورة المورد والإرجاع الجزئي المرتبط بها، مع تحديث المخزون ورصيد المورد ومقارنة آخر الأسعار وإصدار PDF.
- المصاريف المصنفة والمتكررة، سجل الصندوق المرتبط بالأداءات النقدية، عروض الأسعار، فواتير أولية وطلبات زبناء مرتبطة بالعرض مع تتبع الحالة، الأداءات وتقارير نشاط تشمل الفواتير ووثائق الشراء والمخزون والديون.
- إنشاء PDF ومشاركته لبعض وثائق البيع والمصاريف والأداءات.
- أفوار مرتبط بفاتورة: يتحقق من الكمية المرجعة، يضيفها للمخزون، ويخفض الدين أو يسجل رصيداً للزبون.
- تصدير المنتجات وتقرير النشاط كملفات Excel بصيغة XLSX، مع المشاركة عبر تطبيقات الهاتف.
- تصدير نسخة احتياطية JSON واسترجاعها يدوياً عبر النسخ واللصق، مع التحقق من بنية النسخة قبل الاسترجاع.
- الواجهة بالعربية والفرنسية مع اتجاه RTL/LTR، وحفظ البيانات محلياً. أضيفت إدارة المشاريع وربطها بالزبناء، وتتبع أداءات الموردين والمرتجعات، وحساب الربح الإجمالي اعتماداً على تكلفة المنتج وقت البيع. حسابات الزبناء تشمل الرصيد الافتتاحي وسقف الدين وأجل الأداء وكشف الحساب PDF.

## البناء والفحص
GitHub Actions يشغّل اختبارات المستندات وفحص TypeScript عند تحديث main، ويبني APK من نوع Release مع اختبار Android ومراجعة MobSF عند تشغيل البناء يدوياً.
ملف APK الناتج موقّع بمفتاح مؤقت ينشأ لكل تشغيل CI بغرض التجربة الداخلية فقط. هذا التوقيع ليس مفتاح إصدار دائم؛ لا يمكن ضمان التحديث فوق نسخة سابقة موقعة بمفتاح آخر. قبل النشر أو التوزيع المستمر يجب إعداد مفتاح توقيع دائم محفوظ خارج المستودع في GitHub Actions Secrets.
إعداد Android يحدد الحد الأدنى API 29 ويمنع cleartext traffic، ويحذف صلاحيات التخزين والـ overlay غير المطلوبة.
نجاح البناء أو MobSF لا يثبت اكتمال الوظائف ولا يغني عن اختبار التطبيق على جهاز Android فعلي ومراجعة تقرير الفحص.

## وحدات منطق الأعمال
الموجود حالياً يشمل المنتجات والعملاء والموردين والمبيعات والمشتريات والمخزون والجرد ونقطة البيع والعروض والفواتير وسندات الخروج والأفوارات والأداءات والمصاريف والمشاريع والتقارير والنسخ الاحتياطي. ما زالت وظائف مثل قارئ الباركود بالكاميرا، الأوامر الصوتية، المهام الميدانية المتقدمة، وبعض سيناريوهات الإرجاع والطباعة بحاجة إلى استكمال وتجربة.

## حدود النسخة
هذا مشروع مستقل لإعادة تنفيذ الوظائف المعروفة، وليس نسخة مطابقة من YanCommerce، ولا يتصل بخادمه أو حساباته. البيانات محلية على الجهاز. المشروع ما زال نموذجاً أولياً، ويلزم استكمال الواجهات والاختبارات قبل الاستعمال التجاري.


Recent workflow additions include linked purchase requests, orders, goods receipts and supplier invoices; supplier returns linked to confirmed supplier invoices and legacy purchases; supplier credit balances; latest supplier price comparison; categorized expenses; and manually generated recurring expenses.

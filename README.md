# HamZa v0.8.0

مشروع Android مستقل باسم HamZa والحزمة `com.hamza.app`.

## الموجود حالياً
- المنتجات مع ثمن الشراء وثمن البيع وهامش ربح الوحدة والربح المحتمل للمخزون، وإضافة/تغيير/حذف صورة المنتج ومعاينة مكبرة والبحث والتعديل، مع حفظ محلي عبر AsyncStorage؛ الزبناء والموردون أيضاً.
- نقطة بيع POS: بحث بالاسم، سلة متعددة المنتجات، تعديل الكمية، تخفيض عام، اختيار الزبون وطريقة الأداء، التحقق من المخزون، تسجيل البيع وتحديث المخزون وإصدار وصل PDF.
- المبيعات والمشتريات وتحديث كمية المخزون، مع سجل حركات المخزون والجرد الفعلي وتسوية الفروقات.
- مرتجعات الزبناء الجزئية: التحقق من الكمية المتبقية، تعديل صافي المبيعات والربح المحسوب بالتكلفة المسجلة، واختيار إعادة المنتج للمخزون أو عدم إعادته.
- سجل أداءات الموردين: دفعات جزئية بالسنتيم، وصل PDF، وإمكانية عكس أداء محذوف مع إعادة حساب الدين المستحق.
- صندوق نقدي أساسي: رصيد افتتاحي، مداخيل ومصاريف نقدية، منع الصرف فوق الرصيد، وتصدير دفتر الصندوق PDF.
- بيانات المنتج تشمل الصنف والماركة والوحدة والنوع/المقاس، مع البحث والاستيراد الجماعي وتصدير CSV.
- كشوف حساب PDF للزبناء والموردين، تجمع الفواتير أو المشتريات والأداءات المسجلة والرصيد المتبقي.
- المصاريف، عروض الأسعار، الأداءات والتقارير الأولية.
- المشاريع: الزبون والميزانية والتواريخ والحالة والملاحظات، مع احتساب مصاريف المشروع من المصاريف المرتبطة به.
- المهام: ربط بالمشروع، المسؤول، الأولوية، موعد الإنجاز، المدة التقديرية، وتغيير الحالة مع الإضافة والتعديل والحذف.
- إنشاء PDF ومشاركته لبعض وثائق البيع والمصاريف والأداءات.
- تصدير نسخة احتياطية JSON واسترجاعها يدوياً عبر النسخ واللصق، مع التحقق من بنية النسخة قبل الاسترجاع.
- واجهة عربية وفرنسية مع تبديل اللغة وحفظ الاختيار؛ ما زالت مراجعة الترجمة الشاملة واختبار تخطيط RTL/LTR مطلوبين.

## البناء والفحص
GitHub Actions ينفذ فحص TypeScript وExpo Prebuild وتجميع Android، ثم يبني APK من نوع Release ويشغّل MobSF static scan عليه.
ملف APK الناتج موقّع بمفتاح مؤقت ينشأ لكل تشغيل CI بغرض التجربة الداخلية فقط. هذا التوقيع ليس مفتاح إصدار دائم؛ لا يمكن ضمان التحديث فوق نسخة سابقة موقعة بمفتاح آخر. قبل النشر أو التوزيع المستمر يجب إعداد مفتاح توقيع دائم محفوظ خارج المستودع في GitHub Actions Secrets.
إعداد Android يحدد الحد الأدنى API 29 ويمنع cleartext traffic، ويحذف صلاحيات التخزين والـ overlay غير المطلوبة.
نجاح البناء أو MobSF لا يثبت اكتمال الوظائف ولا يغني عن اختبار التطبيق على جهاز Android فعلي ومراجعة تقرير الفحص.

## وحدات منطق الأعمال
ما زالت المخازن المتعددة والتحويل بين المخازن، طلبات التركيب والتقنيون وتسجيل ساعات العمل، أوامر الشراء واستلام البضائع والمرتجعات، الصندوق والبنوك، صلاحيات المستخدمين، وإعدادات الشركة والقوالب تحتاج استكمالاً.

## حدود النسخة
هذا مشروع مستقل لإعادة تنفيذ الوظائف المعروفة، وليس نسخة مطابقة من YanCommerce، ولا يتصل بخادمه أو حساباته. البيانات محلية على الجهاز. المشروع ما زال نموذجاً أولياً، ويلزم استكمال الواجهات والاختبارات قبل الاستعمال التجاري.

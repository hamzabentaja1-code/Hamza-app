# HamZa v0.8.0

مشروع Android مستقل باسم HamZa والحزمة `com.hamza.app`.

## الموجود حالياً
- المنتجات مع ثمن الشراء وثمن البيع وهامش ربح الوحدة والربح المحتمل للمخزون، وإضافة حتى أربع صور للمنتج ومعاينتها وحذفها منفردة، والبحث بالاسم والمرجع والباركود أو بالصوت بالعربية المغربية والفرنسية أو بصورة محلية تقارن الشكل العام، مع إملاء اسم المنتج بالصوت قبل تأكيد الحفظ يدوياً، وحفظ محلي عبر AsyncStorage؛ ملفات الزبناء والموردين قابلة للإضافة والتعديل والحذف مع إبقاء أسماء السجلات التاريخية متطابقة عند التعديل.
- نقطة بيع POS: بحث بالاسم أو المرجع أو الباركود، وقارئ الباركود الذي يرسل Enter، سلة متعددة المنتجات، تخفيض عام، الأداء نقداً أو بالبطاقة أو التحويل أو بالدين مع تسبيق، فاتورة ورصيد متبقٍ، تحديث المخزون ووصل PDF.
- المبيعات والمشتريات وتحديث كمية المخزون.
- إنشاء فاتورة مباشرة متعددة المنتجات بلا إنشاء عرض سعر، مع التحقق من مخزون المستودع النشط وتخفيضه مرة واحدة؛ اختيار استعمال رصيد الزبون المتاح، وملاحظات الفاتورة تظهر في PDF.
- المصاريف، عروض الأسعار، الأداءات والتقارير الأولية، مع تصفية ملخص النشاط التجاري بتاريخ البداية والنهاية وتصدير PDF للفترة.
- المشاريع والمهام: حفظ محلي، متابعة الحالة، تسجيل المهام والمصاريف على المشروع، مقارنة المصروف بميزانية المشروع، وتحديد أولوية المهمة وآخر أجل مع التحقق من التاريخ.
- مرتجعات البيع والإشعارات الدائنة: ربط مرتجعات POS بفاتورتها، خصمها من الدين المفتوح، واستعمال رصيد الزبون غير المطبق في بيع POS آجل لاحق أو عند تحويل عرض سعر إلى فاتورة؛ تسجيل رد نقدي جزئي بعد تأكيد المستخدم، وتخفيض رصيد الزبون وتسجيل خروج المبلغ في السجل المالي وكشف الحساب وPDF؛ منع تجاوز الكمية أو الرصيد، وتحديث المخزون اختيارياً.
- تكلفة البيع وهامش الربح: حفظ تكلفة الوحدة وقت تسجيل البيع، عكس تكلفة المرتجع الذي عاد للمخزون، وإظهار قيمة المبيعات القديمة التي لا تتوفر لها تكلفة محفوظة.
- تصدير لائحة المنتجات وسجل المبيعات كملفات CSV قابلة للفتح في Excel والمشاركة من الهاتف.
- تصدير سجل مالي موحد CSV يضم المخزون والمبيعات والمرتجعات والمشتريات والمصاريف والأداءات والديون المستحقة؛ التحويلات البنكية تظهر كسطور مزدوجة متوازنة خارج حساب الربح.
- ديون الموردين: تسجيل المبلغ المؤدى عند الشراء، إضافة أداءات جزئية مرتبطة بكل شراء، منع تجاوز الرصيد، وعرض الإجمالي حسب المورد.
- الصندوق والحسابات البنكية: أرصدة افتتاحية، حركات نقدية، وتحويل مؤكد ومتوازن بين الصندوق وحساب بنكي. أداءات الزبناء والموردين، البيع المباشر وPOS، المبلغ المؤدى عند الشراء والمصاريف ببطاقة أو تحويل كتترابط بحساب بنكي؛ الرصيد كيتحدّث، السحب الزائد كيتمنع، والحساب المستعمل ما كيتحذفش. كاين استيراد CSV لكشف البنك، مطابقة حسب الحساب والتاريخ والمبلغ، تأكيد المطابقات، مقارنة الرصيد الختامي وحفظ سجل التسويات.
- أداءات الزبناء غير المرتبطة بفاتورة محددة تتوزع تلقائياً على أقدم الفواتير المفتوحة، مع حفظ توزيع الأداء للتدقيق والتصدير.
- إنشاء PDF ومشاركته لبعض وثائق البيع والمصاريف والأداءات.
- كشف حساب PDF قابل للمشاركة للزبون والمورد، فيه الفواتير/المشتريات والأداءات والمرتجعات والرصيد الحالي.
- تصدير نسخة احتياطية JSON كملف، واسترجاعها باختيار الملف من الهاتف أو لصق محتواه، مع التحقق من البنية قبل الاسترجاع؛ وتشمل بيانات كشف البنك وتأكيدات المطابقة وسجل التسويات.
- واجهة عربية وفرنسية مع حفظ اللغة واتجاه RTL/LTR؛ اختبار الترجمات النصية ناجح، وتبقى المراجعة البصرية على جهاز Android.

## البناء والفحص
عند كل دفع إلى `main`، ينفذ GitHub Actions الاختبارات الحالية وفحص TypeScript وفحوص Expo. خطوات Prebuild وبناء APK وفحص MobSF وتجربة Maestro على محاكي Android مشروطة بتشغيل workflow يدوياً؛ لم يُبنَ APK في عمليات الدفع العادية.
ملف APK الناتج موقّع بمفتاح مؤقت ينشأ لكل تشغيل CI بغرض التجربة الداخلية فقط. هذا التوقيع ليس مفتاح إصدار دائم؛ لا يمكن ضمان التحديث فوق نسخة سابقة موقعة بمفتاح آخر. قبل النشر أو التوزيع المستمر يجب إعداد مفتاح توقيع دائم محفوظ خارج المستودع في GitHub Actions Secrets.
إعداد Android يحدد الحد الأدنى API 29 ويمنع cleartext traffic، ويحذف صلاحيات التخزين والـ overlay غير المطلوبة.
نجاح البناء أو MobSF لا يثبت اكتمال الوظائف ولا يغني عن اختبار التطبيق على جهاز Android فعلي ومراجعة تقرير الفحص.

## وحدات منطق الأعمال
ما زالت وظائف المحاسبة المتقدمة وتكامل المشتريات تحتاج استكمالاً ومراجعة، وتحتاج الترجمة الفرنسية ومزيد من اختبارات القبول على Android إلى مراجعة بصرية على الجهاز.

## حدود النسخة
هذا مشروع مستقل لإعادة تنفيذ الوظائف المعروفة، وليس نسخة مطابقة من YanCommerce، ولا يتصل بخادمه أو حساباته. البيانات محلية على الجهاز. المشروع ما زال نموذجاً أولياً، ويلزم استكمال الواجهات والاختبارات قبل الاستعمال التجاري.
